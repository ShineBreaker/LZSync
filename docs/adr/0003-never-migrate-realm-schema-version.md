# 绝不改动 realm 库的磁盘 schema 版本，绝不代替客户端做迁移

LZSync 打开任何 .realm 都以动态模式钉死磁盘版本号，该值只读不写；想让库升版本，引导用户用对应 fork 的客户端打开一次。删除一律写软删标记（DeletePending），物理清理由目标客户端兑现。

理由：官方客户端对打不开的 client.realm 的处理是**删除重建**——擅自改版本号或做迁移，一旦出错等于替用户清空游戏数据；版本号是客户端迁移逻辑的输入，工具侧迁移必然与客户端竞速。EZRealmSync 把"不改 schema、不迁移"定为不可违背的纪律，LZSync 继承。

## Consequences

- 跨版本库（如 delta 的 51 与官方 52）天然可读可写：写入集取三方交集（官方基线 ∩ 源列 ∩ 目标列），缺列自然降级。
- 把 Ez 的版本编码（52011）误写进官方库会导致官方客户端立即 SchemaMismatch——Ez 方向的投放永远写 Ez 自己的版本化库文件。
- 测试体系的构造库走显式 schema 建库（C API 实测可用），与产品路径的"钉死动态打开"是两条通道，测试不破例。
